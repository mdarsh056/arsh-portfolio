The Engineering Problem-Solving Framework

A structured breakdown of algorithmic design: converting ambiguous problem statements into mathematically sound, executable logic.

1. The Four-Stage Engineering Pipeline

Whenever a problem is presented, never write code immediately. Follow this progression to minimize logical errors:

Stage 01

I/O Boundary Isolation

Determine exact input types, ranges, edge conditions (zero, negative numbers, overflow boundaries), and required output formats.

Stage 02

Manual Dry Run (Pen & Paper)

Trace sample values by hand through each state change. Verify that your intuition handles every intermediate state before automating.

Stage 03

Flowcharting & Pseudocode

Formalize decisions into conditional branches, loops, and terminal checkpoints without worrying about language-specific syntax errors.

Stage 04

Complexity & Code

Translate the pseudocode into typed code. Analyze runtime growth $\mathcal{O}(N)$ and auxiliary memory footprint $\mathcal{O}(1)$.

2. Standard Pseudocode Specification

Clean, language-agnostic pseudocode for detecting a Prime Number using the $\mathcal{O}(\sqrt{N})$ trial division optimization.

is_prime.algo Optimized Pseudocode 
ALGORITHM CheckPrime(N):
    INPUT: Integer N
    OUTPUT: Boolean (True if prime, False otherwise)

    IF N <= 1 THEN
        RETURN False
    IF N <= 3 THEN
        RETURN True
    IF (N MOD 2 == 0) OR (N MOD 3 == 0) THEN
        RETURN False

    SET i = 5
    WHILE (i * i) <= N DO:
        IF (N MOD i == 0) OR (N MOD (i + 2) == 0) THEN
            RETURN False
        SET i = i + 6
    END WHILE

    RETURN True
END ALGORITHM

Why Check up to $\sqrt{N}$?

If a number $N$ has a divisor $d$ greater than $\sqrt{N}$, it must also have a corresponding divisor $N/d$ that is smaller than $\sqrt{N}$. Finding no factors up to $\sqrt{N}$ proves that the number is prime. This reduces steps from $1,000,000$ down to $1,000$ checks for $N = 10^6$.

3. Defensive Debugging Techniques

Structured methods for resolving issues instead of guessing through changes:

  • Trace Tables: Create a table tracking each variable per iteration to pinpoint the exact line where values diverge from expectations.
  • Boundary Testing: Always test values at the edges ($N = 0$, $N = 1$, negative limits, and maximum bounds like INT_MAX).
  • Off-by-One Guarding: Check whether loops should use < or <= when terminating to prevent reading unallocated memory.
  • Sanitizers: Use flags like -fsanitize=address,undefined during compilation to catch undefined behavior and buffer overflows immediately.
